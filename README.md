# Monolith

A made-to-order sneaker ecommerce app built in Flutter — browse a
catalog, customize a sneaker on a live 3D model, and check out, backed by
Firebase.

**Live site:** https://monolithe-sneaker.web.app

## Features

- **Shop & product pages** — browse the catalog, view individual sneakers.
- **3D configurator** — spin a sneaker and recolor each panel (upper,
  sole, stripes, laces) live on a real 3D model via `model_viewer_plus`.
- **Cart & checkout** — a Razorpay-style checkout sheet, demo payment mode.
- **Auth** — Google Sign-In via `firebase_auth` + `google_sign_in`.
- **Orders** — past orders backed by Firestore.

## Stack

- Flutter Web
- [Riverpod](https://pub.dev/packages/flutter_riverpod) for state
  (auth, cart, customizer, and Firestore-backed providers)
- [go_router](https://pub.dev/packages/go_router) for routing
- Firebase: Auth, Firestore
- [`model_viewer_plus`](https://pub.dev/packages/model_viewer_plus) for the
  3D sneaker configurator

## Project structure

```
lib/
  core/
    data/models/       # Product, CartItem, SavedDesign, etc.
    firebase/          # Auth + Firestore service wrappers
    state/              # Riverpod providers
    theme/               # Design-system widgets (buttons, cards, marquee, ...)
    router/              # go_router route table
  features/
    home/ shop/ product/ customize/ cart/ checkout/ auth/ orders/ about/
    shell/               # App shell, header, footer, scroll scaffolding
```

## Running locally

```bash
flutter pub get
flutter run -d chrome
```

Firebase config is checked in via `lib/firebase_options.dart` /
`google-services.json` / `GoogleService-Info.plist` (generated by
`flutterfire configure` against the `monolithe-sneaker` Firebase project).

To use the local emulators instead of the live project:

```bash
firebase emulators:start
flutter run -d chrome --dart-define=USE_FIREBASE_EMULATOR=true
```

## Deploying

```bash
flutter build web --release
firebase deploy --only hosting
```

`firebase.json` serves `build/web` as a single-page app (all routes
rewrite to `index.html`, so `go_router`'s client-side routing works on a
hard refresh).
